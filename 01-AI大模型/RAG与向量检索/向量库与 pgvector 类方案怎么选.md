# 向量库与 pgvector 类方案怎么选

## 一句话速记
- **专用向量库**（Milvus、Qdrant、Weaviate 等）：面向大规模、多索引、分布式、过滤、混合查询。  
- **pgvector** 等关系库扩展：适合中小规模、已用 Postgres 做主存、希望向量与**行数据/事务/权限**同库。  
- 下表是**能力取向**对照，落地以各产品当前文档与压测为准。

## 产品取向（抽象对照）

|  | Milvus | Qdrant | Weaviate | ES 向量检索 | pgvector（PostgreSQL） |
|---|--------|--------|----------|------------|------------------------|
| 常见定位 | 大规模、K8s 与云生态常见 | API 与自托管易用 | GraphQL、多模与模块化 | 已有 ES 集群时加「混合搜」 | OLTP+向量同库、行级权限与关系自然 |
| 规模感 | 大、分片 | 中大规模 | 中大规模 | 看集群与索引 | 单库多在中等；更大要分区与调优 |
| 元数据过滤 | 强 | 强 | 强 | 强（DSL 成熟） | SQL WHERE 与业务同模 |
| 运维 | 要配套存储/编排 | 相对轻 | 中 | 若已有 ES 团队则省 | 熟 Postgres 则省 |
| 典型取舍 | 要专库能力 | 要自托管+好 API | 要多模+模块 | 搜索与向量一栈 | 量不是天文+要事务同库 |

## 与「只存文件 + 内存 Faiss」

- 原型可用 **FAISS / hnswlib** 等**本地** 索引 + **自管** 元数据。  
- **上生产** 往往要**持久**、**HA**、**多租户** 隔离、**权限**、**可观测** → **进** 专用库或**至少** 托管方案。

## 延伸追问

- **Q：为何不用 MySQL 存向量？**  
  答：传统**行存**+**B 树** 不为**高维** 近邻 优化；**有** 插件/版本在跟，**但** 与**专用 HNSW/IVF** 生态比，**大** 规模与**调参** 材料常**不如** 专库/ES 成熟，**要** 看**量** 与**版本**。

- **Q：元数据 + 向量** 必须同库吗？**  
  答：**不** 必须，但**同库** 减少**两致性** 与**跨** 系统**对账**；**大** 规模常 **ID 外** 在**行存**、**向量** 在**专** 库，**用** **业务 ID** 回联。

- **Q：HNSW / IVF 怎么背？**  
  答：**HNSW**：图+贪心，**快**、**高召回** 常用，**内** 存与**建索引** 成本**高**；**IVF / PQ**：**省** 空间、**可** 扩**极** 大库、**要** 调**聚类/量化** 参数。**实** 选看**量** 与**延迟** 预算。
